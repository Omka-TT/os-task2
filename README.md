# Лабораторная работа — вариант B

## Запуск
    ./report.sh <каталог> <ERROR|WARN> [--top N]
    ./hello.py <файл>

Формат логов: `дата время УРОВЕНЬ модуль сообщение`.
При ошибке аргументов скрипт печатает справку в stderr и возвращает код 1.

## strace для python3 hello.py (файл trace.txt)
- Всего системных вызовов: **559**.
- Относятся к чтению файла data/01.log: **8** (openat, fstat, lseek, lseek,
  fstat, read, read, close). Данные читают два read: 245 байт и 0 байт (EOF).
- Остальные (551) — накладные расходы интерпретатора: execve и загрузка
  самого python3, поиск и загрузка динамических библиотек (openat, read, mmap,
  mprotect, close), инициализация памяти (brk, mmap), настройка локали и
  часового пояса, поиск и чтение модулей стандартной библиотеки и .pyc-файлов
  (stat, openat, read, lseek), чтение самого hello.py, настройка сигналов.

## Сравнение cat и python3 (файлы trace_cat.txt и trace.txt)
| Программа | Число системных вызовов |
|-----------|-------------------------|
| cat       | 119                     |
| python3   | 559                     |

Вывод: python3 делает примерно в 4,7 раза больше системных вызовов. `cat`
почти сразу читает файл, а интерпретатору сначала нужно поднять среду
выполнения (библиотеки, модули, кодировки), поэтому на запуск уходит
большая часть вызовов, а на полезную работу — только 8.

## Контрольные вопросы
1. Прямой доступ к диску из пользовательской программы запрещён: иначе любая
   программа могла бы читать и портить чужие данные и ломать файловую систему.
   Доступ к устройствам разрешён только ядру (привилегированный режим);
   программа обращается к нему через системные вызовы, а ядро проверяет права.
2. Системный вызов дороже. Нужно переключиться из пользовательского режима в
   режим ядра и обратно, сохранить регистры, проверить аргументы и права, плюс
   ухудшается работа кэшей процессора. Обычный вызов функции — это переход
   внутри одного процесса без смены режима.
